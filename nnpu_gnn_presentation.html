Positive-Unlabeled Learning on Graphs

Non-negative PU Loss
for Graph Neural Networks

Why treating every unlabeled node as a confirmed negative quietly poisons message passing — and how the non-negative risk correction keeps deep GNN backbones from memorizing that mistake.

Problem

The PU problem on graphs

In many node-classification tasks — fraud rings, drug–target interactions, cited-prior-art detection — you only ever get confirmed positives. Everything else is unlabeled, not negative.

Why plain BCE breaks down

Binary cross-entropy needs a 0/1 target for every node. The easy shortcut — label every unlabeled node y=0 — silently asserts something you never verified: that none of them are secretly positive.

  • Label bias. Some fraction π of the "negatives" are actually unverified positives, so the model is trained against corrupted ground truth from step one.
  • Confident wrongness. BCE doesn't just under-perform — it actively pushes hidden-positive nodes toward the negative decision boundary, with full gradient force.
  • Compounding at scale. The more unlabeled nodes dominate the graph (typical in PU settings), the more the loss surface is shaped by mislabeled examples.

A concrete setting

A transaction graph where P = accounts a fraud team has manually confirmed. Every other account is U — almost certainly mostly innocent, but with real fraud rings still hiding inside, undetected precisely because they look like everyone else.

Treating U as ground-truth negative teaches the model that fraud looks exactly like the confirmed cases and nothing else — the opposite of what you want it to learn.

Mechanism

Message passing amplifies the bias

A GNN doesn't just misclassify individual nodes — it launders the mistake through the graph structure, one aggregation step at a time.

hv(l) = UPDATE( hv(l−1), AGG{hu(l−1) : u ∈ N(v)})

Layer-l embedding of node v = combine its own prior embedding with an aggregate of its neighbors' embeddings.

  • Neighborhood contamination. If a hidden-positive node's neighbors were all pushed toward "negative" by BCE, its own aggregated features drift the same way — even before its own label term is applied.
  • Feedback loop. That drifted embedding gets re-aggregated into its neighbors on the next layer. Over L layers, one mislabeled region can bias a whole neighborhood's representations.
  • Depth makes it worse, not better. Deeper GNNs have more capacity and more aggregation steps to fit the false-negative signal exactly — the opposite of the robustness we usually expect from depth.
Key idea — the loss function and the aggregation operator interact. A biased per-node loss doesn't stay local; smoothing over the graph spreads it. Fixing the loss (nnPU) has to happen before the bias gets baked into shared representations.

Theory · I of III

Standard BCE on node predictions

The baseline every PU correction is measured against.

LBCE = − 1n Σ [ yilog(g(xi)) + (1−yi)log(1−g(xi)) ]

Averaged over all labeled nodes i = 1…n; g(xi) is the model's predicted P(y=1) for node i.

g(xi) the GNN's sigmoid output for node i yi ∈ {0,1} — the (assumed) ground-truth label
The catch: BCE has no notion of "unverified." The moment you set yi = 0 for every node in U, you've told the optimizer those labels are exactly as trustworthy as the confirmed ones in P. They are not.

Theory · II of III

uPU — an unbiased risk estimator

Instead of guessing labels for U, decompose the true risk algebraically so it only ever needs P and U — no negative labels required.

R(g) = πRp+(g) + Ru−(g) − πRp−(g)

du Plessis et al., 2014/2015 — the unbiased PU risk, written without any clamp.

Rp+ risk on P nodes, scored as if labeled +1 Ru− risk on U nodes, scored as if labeled −1 Rp− risk on P nodes, scored as if labeled −1 π the class prior, P(Y=+1)

The intuition

Treat every node in U as negative (that's Ru−), then algebraically cancel out the π fraction of hidden positives you know are secretly sitting inside U — by subtracting how those same positives would score if you evaluated the labeled set P under a negative label instead.

Why it's still fragile

With flexible models — and GNN backbones are very flexible — the model can drive Ru−(g) down faster than the correction term keeps up. The subtraction Ru− − πRp− can go negative, which is a mathematical impossibility for a real risk — a symptom of overfitting, not a valid solution.

Note — you'll sometimes see this whole expression written with a max(0, ·) already wrapped around the last two terms: R(g) = πRp+(g) + max(0, Ru−(g) − πRp−(g)). That clamp is exactly the contribution nnPU adds — covered next.

Theory · III of III

nnPU — the non-negative correction

Kiryo et al., 2017 fix uPU's blow-up with one change: floor the correction term at zero.

Rpu(g) = πRp+(g) + max(0, Ru−(g) − πRp−(g) )

The only difference from uPU: max(0, ·) around the correction term.

What the floor actually does

Whenever the correction term would dip negative — the model over-explaining U as negative — nnPU clamps it to exactly 0 for that step. In practice, implementations go one further: they run a small gradient-ascent step on the negated term instead, actively pushing the model back toward less negative-confident predictions on U.

Why this matters specifically for GNNs

Deep GNN stacks are exactly the high-capacity regime where uPU's overfitting shows up fastest — more layers and parameters mean more ways to drive Ru− toward zero on the training partition. The non-negative floor is what makes nnPU practically usable with multi-layer GCN / GAT / GraphSAGE backbones instead of only shallow linear models.

Parameter

The class prior π

Every term in uPU / nnPU is scaled by a single number: π = P(Y=+1), the true fraction of positives across P ∪ U.

What it controls

π sets how much weight the "positive-flavored" correction πRp− gets when it's subtracted back out of Ru−. It is literally an estimate of how many hidden positives are sitting inside U.

Getting it wrong is costly

π too low — under-corrects, the loss still behaves closer to naive BCE, bias persists.
π too high — over-corrects, the negative-risk term goes negative more often, triggering the nnPU clamp constantly and starving the model of gradient signal.

How it's estimated in practice

  • Domain priors. Historical fraud rate, known contamination rate in a labeled audit sample, or a regulatory base rate.
  • Mixture proportion estimation (MPE). Algorithms (e.g. KM1/KM2, elkan & noto) that estimate π directly from the P and U feature distributions.
  • Cross-validated grid search. Sweep candidate π values, pick the one that best matches held-out precision/recall behavior on a small verified subset.

In GNN pipelines, π is usually treated as a fixed hyperparameter for the whole graph, not something learned per-node.

Implementation

Masks in the GNN pipeline

nnPU's math is per-node; a GNN's forward pass is over the whole graph. Masks are how the two meet.

Four boolean masks, one graph

  • train_pos_mask — nodes with a confirmed positive label (P). Used only in the πRp+ and πRp− terms.
  • train_unl_mask — every other training-partition node (U). Used only in the Ru− term.
  • val_mask / test_mask — held-out nodes with fully known ground truth, used only for evaluation metrics — never inside the loss.
Non-obvious but critical — train_pos_mask and train_unl_mask are disjoint subsets of the same train_mask. A node is never in both; unlabeled nodes stay unlabeled even if they're secretly positive — that's the entire premise of PU learning.

Forward pass stays transductive

The GNN runs a full-graph forward pass — model(x, edge_index) over every node, train/val/test alike — because message passing needs the real neighborhood structure to produce correct embeddings, even for nodes that contribute no loss.

Masking happens after the forward pass, only at loss computation: you index logits[train_pos_mask] and logits[train_unl_mask] to build Rp+, Rp−, and Ru−. Val/test logits are computed but simply never touched by loss.backward().

Summary

      
Takeaways


      

        
    
          
  • BCE assumes what PU learning explicitly doesn't know — that unlabeled means negative. On a graph, that wrong assumption spreads through every aggregation step.
    • 
          
  • uPU fixes the bias algebraically, but its correction term has no floor — and high-capacity GNNs are exactly the models that will find and exploit that gap.
    • 
          
  • nnPU's max(0, ·) floor is a small formula change with an outsized practical effect: it's what makes PU learning viable on deep message-passing architectures at all.
    • 
          
  • The class prior π is doing real work in every term — treat estimating it as a first-class modeling decision, not an afterthought.
    • 
          
  • Masks, not subgraphs. Always run the full-graph forward pass; only the loss computation should ever be masked.
    •
